## 目标与边界

继续复用现有 Rust 身份、路由签名、Noise、WebRTC 媒体/控制协议。移动端和浏览器先定位为主控，不承诺通用手机被控能力。服务端仍只负责信令及短期 ICE 配置，不解密媒体、文件和输入。无默认公共服务、账号或后台控制授权。维持桌面端与旧客户端的签名协议兼容，无弱化认证的浏览器专用路径。

## 架构决策前置

- 浏览器端不能假设可以直接运行 Rust 原生 GStreamer、系统凭据存储或与桌面相同的 Noise 库。需先证实 WebRTC SDP/certificate API 能满足当前签名绑定，不采用“仅信令 WSS 就可信”的弱化模式。
- 不在客户端嵌入服务器/TURN 长期共享密钥；管理身份与设备控制身份分开。
- Android/iOS 选择本地媒体和安全存储的成熟平台能力；不实现隐藏服务、后台录屏、锁屏控制或自动输入授权。
- 管理端先本地/离线、明确管理员操作；未授权的公网部署不进入实施范围。
- 新协议 profile 与旧版协商应采用明确版本和能力拒绝，不自动回退至未签名通道。
