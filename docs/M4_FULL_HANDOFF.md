- M4.1–2: persisted exact policies stored in local trust SQLite with foreign-key cascade. Each policy specifies verified peer key/server ID and WSS URL, host slot-zero identity, one display and geometry, view/control permission, initial quality, relay, extended option and 1/7/30-day expiry. Duplicate replacement requires explicit revoke. Locally activate one policy from Host & service; fixed auto-approval only after the media sidecar presents its expected native identity and authenticates registration. No automatic login activation, recurring rearm, boot service, locked-screen permission or background capture. Policy expiration is monitored during the session by wall and monotonic clock; pin/policy revocation stops armed sessions and parent lifecycle cleanup remains. At activation display geometry/name/ID must still match. Physical device and restart workflow not yet verified. Policy expires without silently changing scope. No file/audio/clipboard/power grant.
- M4.5: experimental X11 keyboard/pointer adapter via x11rb 0.13.2 XTEST. Requires actual local Xorg (not Wayland), a single approved primary monitor and matching root geometry, evdev XKB rules, and logind Active=yes/LockedHint=no/Remote=no/Type=x11/Class=user/Display match for production input/capture during control. Reject unsupported session metadata, nonlocal DISPLAY, unexpected geometry, and keys outside an explicit HID map. Key down requires visible focused window inside display; release remains possible after focus or lock changes. Logind state is sampled and is not a guarantee against all compositor/lock races. Existing X11 view-only mode is unchanged; it has no verified lock-screen lifecycle. Linux native control candidate uses temporary identity only. New unit tests plus actual XTEST pointer, key press/release and button fixture in a disposable CI Xvfb, without production test bypass. Physical desktop interoperability pending. Linux debug development archive workflow added (not installer/release).

M4.8/9: virtual display and physical privacy display require platform-native integration and validation; remain unsupported. M4.2 permanent cross-restart unattended listener and privileged service not implemented. New commit CI pending, no production release or deployment.
