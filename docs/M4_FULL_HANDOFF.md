## Third integrated batch — Portal, reviewed power, supervised service
- Verified baseline 374e77f: Core 45737156826, media 45737156882, desktop 45737156838 and Linux X11 45737156840 succeeded; a6a4065 Windows/macOS packages 45737071509 succeeded. These do not verify this new batch.
- Wayland: explicit local ScreenCast portal source selection after authenticated view-only media readiness, one source, no restore token, no XWayland or direct compositor fallback. A restricted PipeWire remote FD and selected node feed a bounded GStreamer RGBA pipeline. View-only peers may wait for the OS picker; source selection is not a remote path. Local cancel, portal closure or stream failure ends sharing. Initial adapter accepts ScreenCast portal interface versions 2–5 and embedded cursor; version 6+ requires stable serial targeting and is intentionally rejected. Actual Wayland compositor integration is unverified. Portal monitor/window/virtual source availability is queried locally; virtual monitors only when the installed compositor advertises support. No Windows/macOS virtual display driver, no Wayland input, no physical display blackout. Window-only sharing is a privacy-preserving alternative, not a physical privacy mode.
- Dependencies: ashpd 0.14.0 (existing XCap dependency, direct use on Linux), futures-util 0.3; Winit/softbuffer Wayland features. References: https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.ScreenCast.html ; https://docs.rs/crate/ashpd/0.14.0 ; https://github.com/PipeWire/pipewire/blob/master/src/gst/gstpipewiresrc.c . License/transitive distribution audit remains required. CI verifies compilation, plugin and bounded conversion only; real compositor consent and virtual stream tests require physical desktop.
- Reviewed power: signed distinct profile 26 (inert) / 27 (real), VIEW routing bit only, no real capture/input. Single enumerated shutdown or restart; exact local host second confirmation via session/action review token. Native sidecar never invokes power commands. Desktop supervisor requires the matching delivered approval, authenticated receipt and successful route closure, checks revocation before submitting fixed native OS operation. Windows shutdown.exe /t 0 without /f; macOS System Events via fixed osascript; Linux systemctl poweroff/reboot, no shell or elevation or forced termination. OS may reject, prompt, or cancel; an approval receipt is not proof of actual reboot/shutdown. CI exercises only inert protocol plus command construction, never invokes real shutdown. No access policy automatically grants power.
- Saved host policy: optional locally activated supervised service, at most three sequential sessions or 30 minutes (whichever first; policy expiry may shorten it). Each successful session must confirm input release; any failure, cancellation, expired or changed policy, missing display, or stop ends service. Existing exact policy and host identity checks, fresh signed sessions and display revalidation apply. No auto-start of remote access at login, no recurring rearm after error, no privileged background service or lockscreen access. Visible main application and existing tray/close revocation remain mandatory. Unit tests cover rearm decisions; physical repeated-session acceptance pending.
